## 實驗: 評估 Zustand vs TanStack Query 狀態管理
**日期**: 2025-01-30
**目標**: 選擇最適合專案的狀態管理解決方案
**方法**: 分別實作簡單的用戶狀態管理，比較開發體驗和效能

### 結果
- **Zustand**: 程式碼簡潔，學習成本低，適合客戶端狀態
- **TanStack Query**: 專為伺服器狀態設計，自動快取和重新獲取功能強大

### 結論
採用混合方案：
- 客戶端狀態（主題、UI 狀態）使用 React Context
- 伺服器狀態（API 資料）使用 TanStack Query

### 後續行動
已採用此方案，在專案中實作完成。

## 實驗: 比較 Jest vs Vitest 測試框架
**日期**: 2025-01-30
**目標**: 評估哪個測試框架更適合 Next.js 專案
**方法**: 設定兩個測試環境，測試相同的元件

### 結果
- **Jest**: 成熟穩定，社群資源多，但設定較複雜
- **Vitest**: 更快的執行速度，與 Vite 整合良好，設定簡單

### 結論
目前專案使用 Next.js 內建的 Jest，暫時不更換。
未來如果轉移到 Vite，可以考慮 Vitest。

### 後續行動
保持關注 Vitest 發展，記錄在技術債務中。
